# v4.4.7 — Smart worker pool: পুরোনো primary auto-fix (versionCode 53)

**Release:** versionCode **53**, versionName **4.4.7** · Worker API **v50** (অপরিবর্তিত)
**Canonical primary:** `https://convo-chat-companion.mr4425390.workers.dev`

## সমস্যা (Problem)

Smart worker pool স্ক্রিনে **Primary worker** ফিল্ডটি read-only — এটি Firebase RTDB-র
`config/app_settings/workerUrl` (বা `webhookUrl`) থেকে লোড হয়। লাইভ RTDB-তে এখনো পুরোনো
বাতিল URL `https://solitary-hill-dcdc.mr44253990.workers.dev` প্রাইমারি হিসেবে সেভ করা ছিল,
আর নতুন URL-টি একটি disabled secondary ("convo") হিসেবে পড়ে ছিল। আগের কোড-ডিফল্ট ঠিক করলেও
সেভ করা ভ্যালু বদলায়নি, তাই স্ক্রিনে পুরোনোটিই দেখাত।

## সমাধান (Fix) — অ্যাপ নিজে থেকে ঠিক করে (self-heal)

`WorkerRouter`-এ কেন্দ্রীয় হেল্পার যোগ হয়েছে:
- `isRetired(url)` — `solitary-hill-dcdc` নাম বা টাইপো সাবডোমেইন `mr44253990` শনাক্ত করে।
- `normalizePrimary(url)` — blank/invalid/retired হলে canonical নতুন primary ফেরত দেয়।
- `cleanPool(nodes, primary)` — retired worker এবং primary-র ডুপ্লিকেট node বাদ দেয়।

`ChatViewModel`-এ:
- স্টার্টআপে cached `webhook_url` এখন `normalizePrimary` দিয়ে নরমালাইজ হয়।
- `listenToGlobalConfig` লাইভ কনফিগ পড়ে primary নরমালাইজ করে ও pool পরিষ্কার করে; **অ্যাডমিন
  হলে** RTDB-তে একবার লিখে দেয় (`webhookUrl`/`workerUrl` = নতুন URL, `workerPool` = পরিষ্কার)।
  লেখার পর listener আবার clean ডাটা পায়, তাই আর লেখে না (কোনো লুপ নেই)।
- `updateWebhookUrl` ও `saveWorkerPool` এখন retired/ডুপ্লিকেট URL সেভ হতে দেয় না।

ফল: অ্যাডমিন নতুন APK খুললেই প্রাইমারি = নতুন URL, pool খালি — **শুধু নতুনটিই থাকে**।
অ্যাডমিন না হলেও ক্লায়েন্ট মেমোরিতে নতুন primary ব্যবহার করে; অ্যাডমিন একবার ঠিক করলে সবাই পায়।
